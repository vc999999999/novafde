# SkillForge 前端 PRD

## 1. 产品目标

SkillForge 面向了解业务但不熟悉 Skill 文件规范的个人用户。前端只收集用户真正拥有的业务事实，Skill 的触发描述、详细步骤、文件结构和输出标准由项目封装的 Skill Creator Agent 决定。

成功标准：

- 用户能在四个输入步骤内完成 Skill 创建。
- 页面不要求用户理解任务类型、文件上下文、`references/`、`scripts/`、`assets/` 或 SkillIR。
- 强制规则和用户提供的常见错误能够完整进入生成结果。
- 用户能看到生成进度、文件预览、校验结果并下载 zip。
- 页面支持桌面、平板和移动端。

## 2. 产品范围

包含：

- 四步 Skill 创建向导。
- 草稿自动保存。
- LLM Provider 配置和连接测试。
- 生成进度、文件树、`SKILL.md`、校验报告和 zip 下载。
- 单人历史记录。
- 本地安装、启动和 CLI 命令说明。

不包含：

- 多人协作、权限和团队空间。
- Marketplace、在线发布和计费。
- 用户手动设计 Skill 文件结构。
- 用户手动配置生成自由度、校验严格度或是否生成安装说明。

## 3. 创建流程

### 第一步：基础信息

用户输入：

- Skill 名称，必填。
- 目标平台，必填，可多选 Claude Code、Codex、Hermes/OpenClaw。

系统处理：

- 根据 Skill 名称自动生成安全的文件夹名称。
- 根据用户内容自动判断输出语言。
- 使用设置页中启用的 generation Provider。

### 第二步：用途与执行流程

用户输入：

- 什么时候使用，必填。
- 希望得到什么结果，必填。
- 大致怎么做，必填，至少一个有顺序的主要阶段。
- 怎样算完成，必填。
- 特殊情况如何处理，可选。

用户只提供业务流程骨架，不填写每步输入、输出、验证方式和失败处理。详细步骤由 Skill Creator Agent 生成。

### 第三步：知识、规则与依赖

用户输入：

- Agent 需要知道的专业信息，必填。
- 必须遵守的规则，必填。
- 常见错误或反例，必填，包含错误描述、正确做法和错误示例。
- 依赖或协同 Skill，可选。

优先级：

- 必须遵守的规则拥有最高优先级。
- 补充说明、模型输出和自动修复都不能删除、弱化或覆盖强制规则。
- 常见错误或反例必须由用户提供，Skill Creator 不替用户猜测。

### 第四步：补充说明

用户输入：

- 一个自由文本框，可选。

行为：

- 不提供快速粘贴模板、预设标签或聊天回填。
- 不要求内容归类到结构化字段。
- 不填写不影响完整度或生成资格。
- 生成时只作为低优先级背景参考。
- 与普通字段冲突时可以补充或修正普通信息；与强制规则冲突时强制规则优先。

### 确认与生成

- 最后一步按钮显示“确认并生成”。
- 页面展示四个步骤的完成度、总完成度、Provider 状态和自动保存状态。
- 后端返回阻塞校验时，用户可回到表单修改。

## 4. 信息架构

主导航：

- 创建：四步创建向导。
- 历史：最近的草稿和生成记录。
- 规则：当前质量规则。
- 设置：Provider 和默认生成策略。
- 本地运行：安装、启动、诊断和 CLI 指引。

创建页布局：

- 主区域显示当前步骤。
- 侧栏显示完成度、Skill Creator 职责、Provider 状态和自动保存状态。
- 移动端改为单列布局。

## 5. 功能需求

### FR-1 四步表单

- 步骤键固定为 `basic`、`purpose`、`knowledge`、`supplement`。
- 用户可以前后切换，也可以点击步骤指示器。
- 用户修改后 700ms 防抖自动保存。
- 补充说明固定显示为完成，不阻塞生成。
- 必填信息缺失时由后端返回带字段路径的阻塞校验。

### FR-2 用途与流程

- 大致流程使用有顺序的重复输入列表。
- 用户可以新增和删除流程阶段。
- 前端不得要求用户填写逐步输入、输出、验证或失败处理。
- 前端不得要求任务类型、正向触发、反向触发、相关文件类型或相关工具。

### FR-3 知识、规则与依赖

- 专业信息、强制规则和协同 Skill 使用可增删列表。
- 常见错误使用重复编辑器。
- 强制规则区域必须明确展示最高优先级提示。
- 协同 Skill 为空时不阻塞生成。

### FR-4 补充说明

- 只显示一个长文本框。
- 不显示聊天消息、Agent 回复、字段建议或快速粘贴模板。
- 不把补充内容计入必填完成度。

### FR-5 生成与结果

- 生成前必须存在启用且具有 `generation` 角色的 Provider。
- 展示输入归一化、规则注入、工作流拆解、SkillIR、文件渲染、质量校验和打包阶段。
- 结果页展示文件树、`SKILL.md`、校验报告和下载信息。
- 阻塞失败时不能下载。

### FR-6 Provider 设置

- 支持 Claude 和 OpenAI-compatible 协议。
- 支持新增、编辑、删除、启用和连接测试。
- API Key 不得在列表或普通响应中明文显示。
- 支持 generation、repair、validation-explanation 角色。

### FR-7 本地运行

- 展示 `install.sh`、`setup-llm.sh`、`run.sh`、`doctor.sh` 和 `clean-artifacts.sh`。
- 每条命令展示用途、读写文件、网络要求、可重复性和风险等级。

禁止重新加入的用户输入字段：

- `taskType`
- 正向或反向触发场景
- 相关文件类型或工具
- 文件系统上下文
- 输出控制
- Skill 类型
- 输出语言
- 聊天消息和快速粘贴模板

## 7. 验收标准

- 创建页只包含四个输入步骤。
- 基础信息只要求 Skill 名称和目标平台。
- 用途与流程包含五个已定义字段。
- 知识步骤包含专业信息、强制规则、用户提供的常见错误和协同 Skill。
- 补充说明只有一个自由文本框且可留空。
- 页面不出现已删除字段和旧组件。
- 草稿可自动保存并通过最新 API 恢复。
- 生成成功后可预览并下载包。
- `npm run lint` 和 `npm run build` 通过。
